QBToSQL

Architecture showcase

Syncs multiple QuickBooks Desktop company files into SQL Server — each into its own database, on a schedule — without breaking when QuickBooks changes between versions.

.NET 8C#WPF SQL ServerQBXML COMxUnit
  • Drift-proof by design. Raw QBXML payloads land untouched in landing.*; typed dbo.* tables are projected from them. An unrecognised QuickBooks field lands successfully whether or not the mapping knows about it yet, so ingestion cannot break on a version upgrade.
  • Re-runnable projection. Because payloads are never discarded, mapping logic can be revised and replayed against data already captured — a mapping bug is repairable retroactively without re-querying QuickBooks.
  • Multi-tenant by database. A central registry holds the company list and per-company settings; each company is provisioned its own database from the same schema scripts, with one scheduler driving incremental syncs across all of them.
  • Credentials never touch disk in plaintext — SQL and SMTP secrets are DPAPI-protected and scoped to the Windows user, encrypted on write by the property setters.
.NET 8 · 5 schema scripts · 10 transaction types · published as architecture, engine withheld
